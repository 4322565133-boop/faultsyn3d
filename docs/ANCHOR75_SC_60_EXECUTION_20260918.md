# Anchor75与SC-MaxViT：60轮顺序训练实施记录

用户要求：实现新的抽取逻辑，先训练UNet，再训练新模型；epoch上限60。训练、验证仍来自Thebe spatial-v3。下面记录实际实现，取代早期设计中100轮、均匀抽样或绝对0.5%稀疏门槛的建议。

## 训练抽样的实际调整

首先只扫描训练分区正标签与有效支持，得到495个含正例的128³空间单元和62,245个候选锚点。每个单元最多保留128个坐标，先均衡选空间单元，再选其锚点，避免直接按大断层体素总量加权。

构建24,000个中心64³有正例、有效信号≥25%的窗口。实际只有115个（0.48%）正体素比例低于0.5%，因此没有继续坚持“25%窗口必须低于0.5%”这一早期假设：那会过度重复少数区域。

实际使用训练候选密度的25%分位数划分低密度/常规前景，门槛为0.0426036875（约4.26%有效体素）。低密度是相对本批训练候选定义，不能称为物理弱断层。

- 常规池18,000个窗口，覆盖480个锚点空间单元。
- 低密度池6,000个窗口，覆盖353个单元。
- 每个有效batch8：4常规＋2低密度＋2不按标签筛选的随机窗口。
- 每轮2400窗口，共预生成60轮清单；所有模型共享坐标和独立的增强种子。
- 原始128³数据不降采样。正例锚点在中心64³随机位置；边界窗口仅用同分区无效补零，不读相邻划分。
- 池内坐标固定，epoch从池中按空间单元均衡重抽并改变增强；不是每轮都生成24,000个全新窗口。随机分支每轮生成新坐标。记录唯一窗口数，后续可单独研究候选池扩充。

首轮审计：2060/2400（85.83%）窗口含正例，1971/2400（82.13%）核心含正例；覆盖472个含正例空间单元，2243个不同窗口起点，214个补零边界窗口。更多轮统计保存在数据清单。

## 实现与验证

- `scripts/prepare_thebe_anchor75.py`：训练索引、候选池和逐轮坐标清单，带来源与内容哈希。
- `train/dataset_thebe_anchor.py`：清单重放、共同增强、同中心双视野输入和有效掩码。
- `models/sc_maxvit3d.py`：原MaxViT编码器/解码器＋轻量上下文编码＋面内/两侧/自由采样。
- `train/train_thebe_anchor_ddp.py`：四卡DDP、精确配额分发、全验证、断点续训。
- `scripts/check_anchor75_sc.py`：坐标、边界、梯度、清单及GPU可行性检查。
- `scripts/launch_anchor75_sc_60.py`：UNet→SC-MaxViT顺序队列及实时对比图。

SC-MaxViT实际参数量40,286,603，比原40,164,233新增122,370参数。UNet-L为9,643,495参数。新模型读取额外上下文，不能将它和UNet的差异全部归因于注意力；正式论文仍需同FOV对照。

context原始覆盖256×256×128，前两轴带掩码低通/均值下采样为128³，与fine一起旋转/翻转；旋转后交换extent相应轴。方向和偏移在增强后的共同原始索引坐标中定义。无需将缺少物理尺度的方向称为真实断层法向。

已设计并执行的核验结果写入 `reports/anchor75_sc_60/`，以对应JSON是否存在且通过为准；不因脚本存在而视为通过。CPU检查涵盖16种共同旋转/翻转的坐标一致性、跨划分哨兵值、退化方向稳定性、几何梯度，以及无效上下文的恒等回退。

## 训练口径

- 随机初始化，不加载任何已有训练权重；两模型共同训练清单。
- 每模型60轮上限，2400窗口/轮，全局batch8；首选4卡×每卡2窗口。
- 前10轮warmup 1e-6→1e-4，之后按60轮日程cosine至1e-7。
- AdamW，weight_decay=0.01；原0.6 Dice＋0.4 Focal，alpha=0.75、gamma=2，有效128³监督。
- 每轮完整验证2433核心、510,945,619有效体素。按IoU@0.5选权重，同时保存P/R、Dice和2001桶近似AP。
- 测试集不参与本轮训练与模型选择。
- 保存last、best及每10轮检查点。恢复时校验训练预算、清单、源码和优化器/RNG状态。
- 历史MaxViT 0.3954只是不同抽样及100轮日程下的参考线，不是本轮严格同配方架构对照。
